# 海报图片分工清单

## 分工口径

当前数据库有 81 个巡演/系列、825 个城市站。城市站通过 `series_id` 归属系列，前台会复用系列海报，所以不需要为 825 个城市站分别找图。

另外有 1 个没有归入巡演的单场演出：`show_id=30` 的《话剧〈威尼斯商人〉》。因此本轮共收集 **82 张主海报**：81 张系列海报 + 1 张单场演出海报。

分工按数据库中的稳定 ID 轮流分配，避免重复领取：

| 组员 | 数量 | 负责范围 |
|---|---:|---|
| A | 21 | 系列海报 |
| B | 21 | 系列海报 + 单场《威尼斯商人》 |
| C | 20 | 系列海报 |
| D | 20 | 系列海报 |

## 文件命名

文件名只使用稳定 ID，不使用中文、空格或标点，避免跨系统和脚本处理时出错。

- 系列海报：`series_003_poster.jpg`
- 单场演出海报：`show_030_poster.jpg`
- 图片是 PNG/WEBP 时保留真实扩展名，例如 `series_003_poster.png`；`series_003` 或 `show_030` 中的 ID 不得修改。
- 每人先放到自己的目录：`poster_collect/A/`、`poster_collect/B/`、`poster_collect/C/`、`poster_collect/D/`。
- 每张图同时登记来源 URL、来源名称和授权/使用说明；不要只交图片文件。

建议的提交结构：

```text
poster_collect/
  A/
    series_003_poster.jpg
    series_008_poster.jpg
    sources.csv
  B/
    series_004_poster.jpg
    show_030_poster.jpg
    sources.csv
  C/
    series_006_poster.jpg
    sources.csv
  D/
    series_007_poster.jpg
    sources.csv
```

`sources.csv` 至少包含：`entity_type,id,name,file_name,source_url,license,status`。

## 收图后的检查

1. 文件名必须能在本清单中找到，不能自创 ID。
2. 图片主体要与演出名称匹配，优先使用官方海报或官方艺人/剧目图片。
3. 图片至少能正常打开，建议统一为竖版海报比例；不要提交网页截图、损坏文件或带明显无关水印的图片。
4. `sources.csv` 的文件名必须与实际图片完全一致。
5. 合并时将系列图片放入 `backend/static/img/posters/`，再按 `series_id` 更新 `show_series.poster_url`；单场图片按 `show_id` 更新 `show_item.poster_url`。
