## 二、仍需修复的功能问题

### [P1] 正数票价四舍五入为零后，仍能成功零元下单

位置：[admin.py](C:/Users/Mild/Desktop/db_homework-1/backend/api/admin.py:38)，特别是金额量化返回处第 46 行。

在隔离数据库中实际提交：

```json
{"price": "0.001", "total_seats": 1}
```

接口成功创建票档，数据库中保存的价格为 `0.00`；随后通过真实购票接口买入，返回 `code=0`、`amount=0.0`，确实生成了一笔零元订单。

原因是代码先检查原始 Decimal 大于 0，再执行 `quantize(Decimal('0.01'))`，没有检查量化后的金额是否仍大于 0。本机实际使用 MySQL 5.7.44，数据库 CHECK 没有提供 MySQL 8.0 中的强制拦截，因此不能依靠页面最小值或数据库约束兜底。

这是此前未覆盖的原有票价边界遗漏。应在金额量化后再次验证合法范围，拒绝量化为零的输入，并继续保留数据库约束。

### [P2] 恢复图集展示后，大量图片加载失败

位置：[ShowDetail.vue](C:/Users/Mild/Desktop/db_homework-1/frontend/src/views/ShowDetail.vue:128)。

本次新增“演出剧照与图集”，直接显示历史 `show_image.image_url`。对当前 108 条图片记录逐项发送实际 HTTP 请求，结果为 **7 条成功、101 条返回 404**；其中部分 URL 重复，不能理解为 101 个不同文件。

例如演出 1 的三张图中，两张 `/static/img/concert2.jpg`、`/static/img/concert3.jpg` 返回 404。浏览器中已实际看到两个“加载失败”占位。

原任务要求清理额外介绍图片功能、保留历史表和数据；这次恢复展示没有完成该清理要求。如果继续保留图集，也需要先处理资源有效性和失效图片的展示，不能直接把历史地址全部显示出来。

证据：[资源逐项请求](test-results/integration_reaudit_2026-10-15/gallery_resources.json)、[浏览器结果](test-results/integration_reaudit_2026-10-15/gallery_browser_results.json)、[页面截图](test-results/integration_reaudit_2026-10-15/restored-gallery-errors.png)。

### [P2] 海报目录检查仍能误认兄弟目录，保存实际无法访问的地址

位置：[admin.py](C:/Users/Mild/Desktop/db_homework-1/backend/api/admin.py:120)。

实际提交下面的海报地址，创建演出仍然成功：

```text
/static/../static_web/index.html
```

`full_path` 最终落到 `backend/static_web/index.html`。因为字符串 `static_web` 也以 `static` 开头，`full_path.startswith(static_root)` 错误地将它判断为静态图片目录内的文件。

浏览器和 HTTP 客户端规范化后的请求为 `/static_web/index.html`，实际返回 404。该地址无法作为海报访问，说明磁盘文件存在性检查与实际静态资源路由仍不一致，海报保护没有完全修好。

应按路径组件判断目录包含关系，并检查可接受的图片文件类型，使保存规则与实际静态资源路由一致。

上述两个接口边界问题的完整请求结果见[补充边界实测](test-results/integration_reaudit_2026-10-15/edge_results.json)。
