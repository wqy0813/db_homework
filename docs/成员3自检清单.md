# 成员 3 自检清单

> 用途：自己电脑走一遍，把每条勾掉；不通过的写在最下面"问题记录"。
> 依赖：成员 1 已执行 `docs/注册功能数据库升级说明.md` 里的 `ALTER TABLE app_user ...` SQL。

## 0. 环境准备

- [x] 拉取最新分支，确认没有未提交修改冲突
- [x] 确认 `app_user.password_hash` 字段长度 ≥ 255（`DESCRIBE app_user;`）
- [x] 启动后端：`cd backend && python app.py`（或项目约定的启动方式）
- [x] 启动前端：`cd frontend && npm run dev`
- [x] 浏览器打开 `http://127.0.0.1:5000/`，用 `user01 / 123456` 登录成功（确认旧账号没坏）

## 1. 任务 1：用户注册

- [x] 登录页有"注册"入口（按钮或链接）
- [x] 留空用户名 / 留空密码：提示"请输入用户名和密码"
- [x] 用户名 `a`（1 位）：提示"用户名应为 2-50 个字符"
- [x] 用户名 `user@01`：提示"用户名应为 2-50 个字符，仅限中文、字母、数字或下划线"
- [x] 密码 `123`：提示"密码长度应为 6-64 个字符"
- [x] 密码 `123456`、确认 `654321`：提示"两次输入的密码不一致"
- [x] 手机号 `12345`：提示"手机号格式不正确（11 位数字，1 开头）"
- [x] 邮箱 `abc@`：提示"邮箱格式不正确"
- [x] 正常填写后点注册：成功提示，**自动跳到登录页并填好用户名/密码**（或弹出引导）
- [x] 用刚注册的账号登录：成功
- [x] 再用相同用户名注册：提示"该用户名已被注册"
- [x] 查数据库：`SELECT username, LEFT(password_hash, 7) FROM app_user WHERE username='xxx';` —— 应是 `pbkdf2:` 或 `scrypt:` 开头，**不是明文**
- [x] 演示账号 `user01 / 123456` 仍能登录
- [x] 注册页面里**没有任何"角色/管理员"的字段或选项**（普通用户不能造管理员）

## 2. 任务 2：地址 / 观演人编辑

- [x] "收货信息"页：每条未使用的地址有"编辑"按钮
- [x] 点编辑：弹窗带出原信息，改手机号后点保存：列表更新成功
- [x] 点"取消"或关闭弹窗：列表没变
- [x] 已用于订单的地址，"编辑"按钮置灰 或 点击后提示"为保留历史订单信息，该收货地址不能修改或删除，可以新增一条用于后续购票"
- [x] 已用于订单的地址，"删除"同样被拒
- [x] "设默认地址"按钮：点后该地址的"默认"标签出现，且之前默认的取消
- [x] 退出再登录，默认地址仍然是他（持久化已存在）
- [x] "常用购票人"页：与上面地址一致的 5 个检查项（编辑、保存、取消、保护提示、删除保护）

## 3. 任务 3：导航、返回、筛选

- [x] 顶部菜单能看到"演出巡演"入口
- [x] 从 `/shows`（单场演出列表）点"返回巡演"：跳到 `/series`
- [x] 从 `/series/:id`（城市站详情）点返回：回到所属巡演列表，且筛选条件（城市、状态、关键词）还在
- [x] 从某个演出详情点返回：回到原来的列表，筛选条件还在
- [x] 列表里改了下拉/输入框的值，**不点筛选也不回车**：列表不变
- [x] 改完条件按回车：列表更新
- [x] 点"筛选"按钮：列表更新
- [x] 点"重置"：所有筛选条件清空、列表回到全量
- [x] 在 `/series` 选好城市 + 关键词 → 进巡演 → 进城市站 → 详情 → 返回 → 返回：筛选条件都在
- [x] **F5 刷新当前页**：筛选条件仍在（`sessionStorage` 生效）
- [x] 关闭浏览器标签再打开：筛选条件清空（这是符合预期的，不算 bug）
- [x] 管理员登录后点"退出"：跳到 `/series`（不是 `/shows`）
- [x] 普通用户登录后点"退出"：跳到 `/series`
- [x] 详情页顶部仍有"演出巡演 / 演出列表 / 收货信息 / 常用购票人 / 我的订单"主菜单

## 4. 任务 4：购票页资料补齐

- [x] 用一个**没有地址、没有观演人**的新注册账号登录
- [x] 进入一个**售票中**的演出详情
- [x] 地址下拉旁有"新增地址"按钮，观演人下拉旁有"新增观演人"按钮
- [x] 首次进入时**自动选中默认地址**（如果没有默认地址，则下拉是空）
- [x] 点"新增地址"：弹窗填好保存，地址列表**自动刷新**并**自动选中新地址**
- [x] 新增地址前已选的票档、票数、其他观演人**没被清空**
- [x] 同理点"新增观演人"并保存：列表刷新、自动选中新观演人，已选的其他观演人和票数不变
- [x] 手动切到另一个地址后，**不再被自动改回默认**（即使再点别的下拉也不变）
- [x] 切到另一个场次（不同 session_id）再回来，**之前那个场次选的票档/票数/观演人还在**
- [x] 新增资料失败（后端报错）时，原来选择**不丢失**

## 5. 任务 5：限购、预售、介绍

- [x] 票数输入框支持键盘输入（不只是点 + / -）
- [x] 票数输入 `0` / `7` / `-1` / `1.5`：显示"票数应为 1-6 的整数"或不通过校验
- [x] 票数输入 `1` ~ `6`：通过
- [x] 购票区显示"单笔最多 6 张，每位观演人同一场次限购 1 张"
- [x] 人数 ≠ 票数时：提示"购票人数量必须与票数一致"
- [x] 进入**预售中**的场次：
  - [x] "立即购买"按钮**置灰或禁用**，鼠标悬停有"预售中：开售前可提前完善资料，开售时再购买"
  - [x] 地址/观演人旁仍有"新增地址 / 新增观演人"按钮
  - [x] 弹窗顶部或购票区有"提前填写资料不等于买到票"提示
- [x] 介绍内容含 `\n`：页面上**真实换行**（不是显示 `\n`）
- [x] 介绍内容含多段：分段清晰
- [x] 没有介绍时：显示"暂无演出介绍"（不是空白，也不是报错）
- [x] `/series` 列表的"预售中 / 售票中 / 售罄 / 已结束"和详情页**用同样的字**（不会出现一处"售票中"另一处"在售"）
