# 项目结构说明

本文档说明当前维护的项目结构。系统由 Flask REST API、Vue 3 单页前端和 MySQL 组成。Windows 启动入口为根目录 `start_website.bat`；浏览器入口为 `http://127.0.0.1:5000/app/`。

## 运行与源码目录

```text
backend/
├─ app.py              Flask 入口、API 注册和静态页面托管
├─ config.py           Flask/MySQL 配置（支持环境变量）
├─ db.py               MySQL 连接和查询辅助函数
├─ posters.py          海报名称映射及 /posters/<组>/<文件> 路由
├─ api/                认证、演出、订单、资料、管理和统计 API
├─ static/             Flask 静态目录，管理员上传内容可写入此处
├─ static_web/         Vue 生产构建目录，由 Vite 直接生成
└─ requirements.txt    Python 运行依赖

frontend/
├─ src/                Vue 页面、路由、状态和 API 客户端
├─ public/assets/      构建时复制的静态资源（含 ECharts）
├─ package.json        前端命令和依赖
└─ vite.config.js      /api、/posters 开发代理和生产输出配置

poster_collect/
├─ A/、B/、C/、D/      海报原图及对应 sources.csv
└─ ...                 后端通过 /posters/<组>/<文件名> 直接读取原图
```

海报原件和来源登记以 `poster_collect/` 为唯一维护来源，不需要复制到 `backend/static/img/posters/`。数据库海报 URL 使用 `/posters/<组>/<文件名>`；管理员上传文件保存在 Flask 静态目录。

## 前端构建

在 `frontend/` 执行：

```powershell
npm ci
npm run build
```

Vite 会先清理并直接生成 `backend/static_web/`，因此不会留下前一版 hash 文件。开发模式使用 `npm run dev`，通过 Vite 代理访问本机 Flask API 和海报路由。

## 数据库脚本

```text
sql/
├─ schema/       ddl.sql（完整结构、触发器和视图）；views.sql（单独补建视图）
├─ seed/         seed_data.sql（完整基础演示数据，包括系列关系）
├─ tests/        手动查询和边界测试 SQL
└─ archive/      旧数据库迁移和旧版系列补充数据脚本
```

新建数据库只执行 `sql/schema/ddl.sql` 和 `sql/seed/seed_data.sql`。`ddl.sql` 会删除并重建 `ticket_sales`，`seed_data.sql` 会清空并重载业务数据。`views.sql` 用于已有数据库补建或刷新视图。`sql/archive/` 下的脚本仅供对应旧版数据库升级/追溯，不加入新库初始化流程。

## 维护和验证脚本

```text
scripts/
├─ data/          当前数据生成、归一化、系列分组、状态维护和海报映射工具
├─ tests/         API、海报路由和场次时间规则测试
├─ performance/  SQL 计时与 EXPLAIN 检查
└─ archive/      历史迁移辅助、一次性探查和旧素材工具

test_tools/
└─ ui_test.js     Puppeteer 浏览器流程检查及截图
```

部分 API/UI 测试会写入订单或更新数据库；运行前先检查脚本说明，并使用可恢复的测试数据。不要在有重要数据的数据库上执行会清理/重建数据的脚本。

## 文档和本机文件

- `README.md` 是启动、建库和常用命令的总入口。
- `docs/API接口说明.md` 描述 REST API；`docs/组员部署使用手册.md` 面向新电脑部署。
- 数据库设计正文在 `docs/演出门票销售系统_数据库设计对应内容.md`；模型展示版为 `docs/database_models.md`、`.html` 和 `.pptx`。
- `frontend/node_modules/`、`test_tools/node_modules/` 和 `.pptx-tools/node_modules/` 是可按各自 package lock 重装的依赖。
- `.mysql/` 是当前机器的 MySQL 数据目录，服务运行时不要删除或复制到其他电脑。
- `work/` 是临时预览和调试输出，不作为产品交付目录。
