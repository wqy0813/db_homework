# 项目结构说明

本文档说明当前维护的新版目录。旧版 Jinja2 页面、旧版后端备份和重复启动脚本已经移除；运行入口只有根目录的 `start_website.bat`。

## 运行入口

| 入口 | 作用 |
| --- | --- |
| `start_website.bat` | Windows 一键检查/启动 MySQL，并启动 Flask |
| `backend/app.py` | Flask 后端进程；提供 `/api` 和 `/app/` |
| `http://127.0.0.1:5000/app/` | 新版 Vue 生产页面 |
| `frontend/` | Vue 3 + Vite 开发源码 |

根路径 `/` 只做重定向，不再承载旧页面。生产页面由 `backend/static_web/` 提供；修改前端源码后必须重新构建并同步到该目录。

## 后端

```text
backend/
├─ app.py              Flask 入口、CORS、根路径和 Vue 静态托管
├─ config.py           MySQL 和 Flask Secret 配置，可由环境变量覆盖
├─ db.py               PyMySQL 连接、查询和密码校验辅助函数
├─ api/                REST API 蓝图
├─ static/img/         新版仍使用的海报、艺人图和演出图片
├─ static_web/         Vue 构建产物，Flask 从 /app/ 托管
└─ requirements.txt    Python 运行依赖
```

`backend/static/img/` 不能删除：数据库中的 `poster_url` 仍引用 `/static/img/...`。`static_web/` 是构建产物，不直接编辑其中的压缩 JS/CSS。

## 前端

`frontend/src/` 保存页面、路由、Pinia 状态和 Axios API 封装；`frontend/public/assets/echarts.min.js` 是构建时复制到产物的图表库。常用命令：

```powershell
cd frontend
npm install
npm run dev
npm run build
```

生产构建同步：

```powershell
Copy-Item -Recurse -Force .\dist\* ..\backend\static_web\
```

## SQL

```text
sql/
├─ schema/      ddl.sql、views.sql：数据库结构、约束、视图、触发器
├─ seed/        seed_data.sql、phase4_seed_series.sql：基础和示例数据
├─ migrations/  phase4_series.sql：结构升级
├─ tests/       queries.sql、test_cases.sql：查询示例和数据库测试
└─ backups/     大型备份文件；只用于恢复，不参与初始化
```

`sql/schema/ddl.sql` 会删除并重建 `ticket_sales`，`sql/seed/seed_data.sql` 会清空并重新导入业务数据，执行前必须确认目标数据库并做好备份。

## 脚本

```text
scripts/
├─ data/         数据生成、清洗、巡演聚合、状态维护和图片维护
├─ tests/        API、数据一致性、状态分布检查
├─ performance/ 性能测试和 EXPLAIN
└─ docs/         将数据库设计 Markdown 预处理为 Word 中间稿
```

脚本都从自身位置定位项目根目录，不依赖当前命令行目录。推荐从项目根目录运行，例如：

```powershell
python scripts/tests/test_api.py
python scripts/data/gen_more_data.py
python scripts/performance/perf_check.py
```

### 状态与图片维护

`scripts/data/rebalance_status.py` 是当前销售状态的唯一重平衡入口。它以数据库时间为准：已结束场次设为售罄；每个 `series_id` 最多选择一个有余票且已到开售时间的城市站为在售，其它有余票站点为预售。支持先用 `--dry-run` 预览，正式执行后会在事务内校验重复在售站点、历史未售罄和售罄余票异常。

```powershell
python scripts/data/rebalance_status.py --dry-run
python scripts/data/rebalance_status.py
```

`sql/seed/seed_data.sql` 中的 `ev_session_status` 定时事件只会关闭已结束或无余票场次，不会批量把预售站点提升为在售。新增或批量生成演出后，应重新执行上面的重平衡脚本。

`scripts/data/gen_posters.py` 会优先从 `backend/static/img/artists/` 按主演/系列名匹配真实图片（例如周杰伦），没有匹配素材时才使用分类场景图，并将结果写入 `backend/static/img/posters/` 与 `show_series.poster_url`。新增艺人素材可先运行 `scripts/data/fetch_artist_images.py`，检查图片后再生成海报。

API 测试结果写入 `docs/test-results/test_api_results.json`；文档生成脚本的中间稿写入 `docs/test-results/report_for_docx.md`。

## 测试工具

`test_tools/ui_test.js` 是新版 Puppeteer UI 回归测试，依赖由 `test_tools/package.json` 管理。运行前先启动 Flask：

```powershell
cd test_tools
npm install
node ui_test.js
```

截图保存在 `test_tools/shots/`，UI 结果保存在 `test_tools/ui_results.json`。一次性验证脚本已清理，不作为项目测试入口。

## 本机数据和不应提交的文件

- `.mysql/data/` 是当前本机 MySQL 数据目录，服务运行时不要删除。
- `frontend/node_modules/`、`test_tools/node_modules/` 是依赖缓存，不是源码。
- `__pycache__/`、`*.log`、临时测试输出可随时清理，`.gitignore` 已覆盖常见缓存。
- 生产密码只应通过 `DB_PASSWORD` 等环境变量提供，不要提交真实凭据。
